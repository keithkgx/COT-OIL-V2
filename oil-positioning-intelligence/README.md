# Oil Futures Positioning Intelligence

An **offline-accessible interactive COT dashboard** generated by Python and updated by **GitHub Actions**, without Railway, Streamlit or an always-on server.

**Current MVP:** Official CFTC Disaggregated futures-and-options-combined and futures-only observations for NYMEX WTI, ULSD and RBOB. Combined is the dashboard default; Managed Money is the default trader cohort.

**ICE Brent and Gasoil:** visible as planned instruments but deliberately **disabled**, pending an authorized data connection. The software does not scrape ICE or include ICE-owned datasets.

> The distributed dashboard contains **no fake live market data**. On first installation it displays an empty state until source retrieval succeeds. This project is not a real-time trading signal.

## Trader-desk dashboard upgrade (review branch)

The dashboard now prioritizes **three questions** before the detailed charts: what moved most, where positioning is stretched against its own history, and whether net positions are increasing across the covered markets.

- **As-of week selector:** inspect any observation in the embedded five-year view, without applying future observations to the selected week's display. The default remains the latest available CFTC observation.
- **Desk brief:** a compact three-part comparison using the size of the change relative to the current market's open interest, 3-year net/OI rank, and cross-market directional breadth. These are *descriptive* statistics, not trading signals.
- **Layout:** full-width desk screens, clear separation of market intelligence from the selected market, and accurate lower-quartile commentary.
- **Deep dive:** directional long/short/net chart excludes separately reported spreading to avoid scale distortion; historical net-contribution chart defaults to the latest 12 months.
- **Market overview table:** includes report-on-report changes, four-week changes, 1-year and 3-year percentiles, open interest and explicit observation dates.
- **Market deep dive:** adds historical changes in long versus short positioning, plus a concise four-category participant table.
- **Report basis:** Futures and Options Combined remains the default; Futures Only remains selectable. The two are not additive or directly comparable.
- **Access:** remains a self-contained downloadable HTML file in the private repository. GitHub Pages is not enabled.

**Caveats:** Changes in holdings do not identify individual executions. Current dashboards use the public CFTC data for WTI, ULSD and RBOB; they do not include ICE benchmark Brent or Gasoil. Historic selection uses recorded observation dates rather than publication timestamps. Non-reportable trader positions and price series remain out of scope for this first interface revision.

## GitHub Pages: optional public dashboard (no Railway)

The dashboard can be shared through GitHub Pages without making the historical-data scripts run in the browser. Only the generated `dashboard/index.html` is uploaded to Pages; the private repository remains the data-processing source.

To turn on public hosting **after reviewing the output and confirming it contains no sensitive information**:

1. In the COT-OIL-V2 GitHub repository, open **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. Open **Settings → Secrets and variables → Actions → Variables → New repository variable**. Set the name to `PUBLISH_PAGES` and value to `true`.
3. Run **Actions → Update COT and Dashboard → Run workflow** on `main`. After the update job succeeds, the publish job will upload only `oil-positioning-intelligence/dashboard/` to GitHub Pages.
4. Find the verified live address in **Settings → Pages** or the **Publish public dashboard (opt-in)** job. The expected URL for this repository is `https://keithkgx.github.io/COT-OIL-V2/`, but do not assume it is live until GitHub reports successful deployment.

**Plan limitation:** GitHub Pages on a private repository generally requires GitHub Pro, Team or Enterprise. If Pages cannot be enabled while the repository is private, either make the repository public after reviewing its contents or use a separate public website repository for the generated dashboard. Publishing a site is public internet disclosure even if its source repository remains private.

The `PUBLISH_PAGES` variable prevents failed deployment jobs from interfering with the scheduled CFTC refresh before Pages has been configured. Setting it to `false` stops subsequent public deployments but does not unpublish already public content.

## How the project works

1. Scheduled GitHub Actions job fetches the CFTC PRE Socrata JSON datasets.
2. Python validates the schema and upserts by `(source, market, basis, position_date, cohort)` to `data/cot_history.csv`.
3. Python computes net/gross positions, net/OI, report changes, 7-day/28-day comparisons, attribution and *causal* 1Y/3Y percentiles.
4. A single `dashboard/index.html` is rebuilt. **All Plotly JS and historical chart data are embedded** so it can be opened with a double click, even offline.
5. GitHub Actions commits the data and dashboard only if their contents changed.

## Start locally (Windows PowerShell)

```powershell
cd oil-positioning-intelligence
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:PYTHONPATH="src"
python -m oilcot.cli backfill
python -m pytest -q
start dashboard\index.html
```

On macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
PYTHONPATH=src python -m oilcot.cli backfill
python -m pytest -q
open dashboard/index.html     # macOS; Linux: xdg-open dashboard/index.html
```

`backfill` will download the full history from the selected CFTC dataset(s), which requires internet access. `refresh` fetches a 90-day overlap to pick up revisions. Use `status` to inspect stored observations and `build` to regenerate the dashboard from a previously downloaded CSV:

```bash
PYTHONPATH=src python -m oilcot.cli refresh
PYTHONPATH=src python -m oilcot.cli build
PYTHONPATH=src python -m oilcot.cli status
```

You may set the optional `CFTC_APP_TOKEN` environment variable for higher API quotas. **No token or login is required for ordinary public CFTC requests.**

## Upload to a *new private GitHub repository*

1. Create an empty **Private** repository named `oil-positioning-intelligence` on [GitHub](https://github.com/new). Leave README/license options unchecked.
2. Unzip this project, open a terminal at the project root, then run:

```bash
git init
git add .
git commit -m "Initial CFTC monitor MVP"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/oil-positioning-intelligence.git
git push -u origin main
```

3. GitHub → repository → **Settings → Actions → General → Workflow permissions**: ensure the workflow can write repository content. The YAML declares `contents: write`, but organization policy can restrict that permission.
4. Open **Actions → Update COT and Dashboard → Run workflow** to perform the first cloud backfill. The initial run downloads history and commits `data/cot_history.csv` plus `dashboard/index.html`. The job then checks twice daily (06:37 and 12:37 Singapore time).
5. Open the `dashboard/index.html` file from a local clone, or use **Actions → artifacts** if adding an artifact upload step. GitHub's code preview is not the interactive dashboard; **download or clone the HTML to open it in a browser**.

GitHub Pages is opt-in using the repository variable `PUBLISH_PAGES=true` and the GitHub Pages GitHub Actions source. The public site must contain only authorized public CFTC data, not internal Pertamina information.

## GitHub automation limitations

- Scheduled GitHub Actions can run late or be skipped. Check the Actions log if a report fails to appear.
- The CFTC historically publishes observations for Tuesday on Friday (with holiday exceptions) and has announced plans to publish twice a week. The ingestion uses actual observation dates; it does not assume weekly row spacing.
- The file displays the **COT position date**, not the public release timestamp. Historical CFTC API records do not provide a point-in-time publication timestamp.
- An API schema change, invalid position, changed column or failed request causes the pipeline to fail instead of silently publishing incorrect numbers.
- Git commits of past records are not an immutable "as originally published" archive. Backfilled historical revisions update the canonical store. A revision ledger could be added later.
- The chart payload contains the latest five years of observations for performance, while the canonical CSV retains full history.
- GitHub Actions logs can indicate successful source checks even if no new observation was published; the dashboard's latest *position date* will stay unchanged.

## Metric definitions

- **Net:** `long - short`
- **Gross directional exposure:** `long + short`, excluding separately reported spreading
- **Net/OI:** `100 * (long - short) / open_interest`
- **Net change:** current net less immediately previous report net
- **Long contribution:** new long - previous long
- **Short contribution:** negative of `(new short - previous short)`
- **Weekly / four-week change:** nearest past observation to 7/28 calendar days ago, if within tolerance (missing otherwise)
- **1Y / 3Y percentile:** empirical midrank of a given observation against contemporaneously available week-level observations in the trailing calendar window. Minimum historical observations: 20/60.
- **Absolute-contract percentile:** only compares observations using identical `contract_units`. **Net/OI percentile** is designed to remain meaningful if units change.

Percentiles are **descriptive**, not trading advice. An extreme position does not automatically predict price reversal.

## Known first-run validation step

The code and calculations are tested offline using synthetic fixtures. For Producers/Merchants, no distinct spreading column is published in this report, so spreading is stored as missing (not zero). This build environment cannot access external HTTP hosts, so **a genuine CFTC API download has not been executed here**. The first real GitHub Actions run is the source integration test. If CFTC changes a field name, the workflow will fail visibly with the missing key rather than inventing a mapping. Fix the schema mapping in `src/oilcot/config.py` after checking the actual official response.
